- Catalogue = original curated FILMS (src/data/films.ts) + approved import list (src/data/import-list.ts) merged in src/data/catalogue.ts; identities/public metadata are resolved once by scripts/resolve-catalogue.ts into catalogue-snapshot.json and an audit import-manifest.json, so page loads never search TMDB/OMDb. Titles that can't be confirmed stay off the site; never invent IDs, awards or trailers.
- Import matching supports movie and tv endpoints: documentary genre, title or ':'-subtitle alias, year ±1, uniqueness; tie-breaks only via explicit per-title hints (format, credited filmmaker, search alias).
- Watch providers are fetched live per selected catalogue ID through a server function that rejects non-catalogue IDs.
- Optional enrichment uses a public server function reading runtime-injected process.env secrets inside its handler only; retain the immediate curated first screen so service failures never block discovery.
- TMDB identity requires exact normalized title, documentary genre and every director, allowing at most one year of premiere/distribution variance; verify all candidate details and reject ambiguity before caching an ID.
- Discovery helpers own filtering, trailer validation, Irish provider parsing and tracking keys; test these rules independently from presentation.
- Independent discovery facets and explicit editorial tags live in discovery-facets. Awards come only from the CSV's dated labels; IMDb's one-line award summary is never shown (a November 2026 audit found it crediting BAFTAs from other categories and News Emmys as Primetime). sync-catalogue lists newly added titles whose IMDb summary mentions an Oscar, BAFTA or Primetime Emmy so someone adds the dated label by hand.
- The Directors tab (/directors, /makers redirects by rewrite) lists featured directors (three catalogue titles, minus isFeatured's editorial exclusions) using director-profiles.json: people come from TMDB credits on catalogue films via `npm run resolve-directors`, never a name search, so portraits stay verified. Blurbs in that file are hand-written. /directors/x is the director's shareable page: a filtered gallery with their profile on top, and the film page's director links open it.
- Discovery shelves apply the current filtered, stable order and hide below three titles; URL facets are conjunctive and never fetch catalogue-wide live providers, keeping navigation deterministic and costs bounded.
- Verified alternate director credits use film-scoped normalization shared by TMDB and OMDb; never broaden name matching globally because unrelated people can share names.
- TMDB requests are deduplicated per worker with a bounded catalogue cache and three concurrent requests. The catalogue itself needs no database; the only stored user data is the optional account below.
- OMDb ratings are captured in the snapshot at import by verified IMDb ID with matching movie/series type, preserving the daily quota; omdb.server.ts remains the bounded cached helper for any future runtime refresh.
- Later approved batches are delta imports (`bun scripts/resolve-catalogue.ts --batch2`): reconciled against the pre-batch catalogue by identity key, verified-TMDB collisions merge, resolved manifest entries are reused so reruns make no API calls; title-scoped evidence pins and collections live beside the batch source.
- data/catalogue-master.csv is the single source of truth for title, year, type, category, tags, mood, director and TMDB/IMDb IDs. src/data/catalogue-sheet.json is generated from it by `npm run sync-catalogue`: never edit that JSON by hand. Titles absent from the CSV are dropped; status=new rows are matched on TMDB and set live, and uncertain matches stay new and are listed. Enrichment stays in catalogue-snapshot.json, keyed by id.
- `npm run sync-catalogue` also rewrites public/sitemap.xml and the robots.txt pointer from SITE_ORIGIN; rerun it after changing the domain.
- Tags are limited to the approved slugs in src/data/tags.ts; the sync rejects anything else.
- Discovery navigation uses one sticky grid for header, tabs and chips; category and browse-chip selections clear the Spotlight film so filtering always opens Gallery.
- Clean URLs (/tags/x, /categories/x, /directors/x, /film/x) are router rewrites onto the home route's search params in src/lib/site-urls.ts; keep filtering on the one route. Link previews come from pageHead and are server-rendered. SITE_ORIGIN there must match the live domain; rerun `npm run og-images` after adding a tag or category.
- Providers come from TMDB for one visitor-selected country; one cached response serves every country.
- Google Analytics loads only after consent (src/lib/analytics.ts). Messages and suggestions are emailed to the owner via an Apps Script webhook in the FEEDBACK_WEBHOOK_URL secret (docs/feedback-email.gs).
- Each film's awards are one `awards` CSV column (labels split on ";"), from an approved list only: Oscars (wins and nominations), BAFTA and Primetime Emmy (wins), Sundance Grand Jury/Audience/Directing, Tribeca, IDA, and Cannes Palme d'Or/L'Œil d'or. Wikidata has no Tribeca, IDA or Primetime Emmy data, so those need other sources. Hark audited every film against the official lists in November 2026 (docs/awards-to-check.md). Primetime craft wins count, as one label per film when it has no main Emmy, e.g. "Emmy Winner – Directing 2019"; IDA series labels are "IDA Best Episodic Series" and "IDA Best Limited Series". Pre-2010 IDA wins are left out until confirmed from IDA's own records. award-bodies.ts maps labels to icon, colour and prestige order. The Awards tab (/awards, /awards/x) groups by body and opens on an overview, like Directors. Prestige order is Oscar, BAFTA, Cannes, Emmy, Sundance, Tribeca, IDA, wins before nominations. Every body with a film gets a pill (Tribeca has two); overview rows still need three. Award lists sort by the award's own year (the label's, not the film's), newest first, and /awards/oscars splits into Winners and Nominees. Film-page award labels are links to their award page, and film JSON-LD lists won awards (never nominations) in `award`.
- The netflix-original tag is set by hand in the CSV: only titles Netflix commissioned or acquired and released as Netflix Originals, wherever they stream now. It used to be generated from streaming availability, which wrongly caught licensed films. /tags/on-netflix still works through OLD_TAGS in site-urls.
- The CSV's netflix_id column holds Netflix title IDs from Wikidata P1874, each checked against Netflix's own title page; never guess one. The film page's "Watch on Netflix" button needs that ID and Netflix in the live providers for the visitor's country.
- Film pages end with "More from [Director]" (two or more other titles) and "More like this" (topic tags, then category, shuffled by seededRandom(film id) so the server renders the same links every time); the rules are moreFromDirector and moreLikeThis in discovery-facets.
- About is a browse tab on the home route (/about rewrites to it) so it keeps the shared header. Tags wrap below the sticky nav so they don't fill a phone screen.
- Browse tabs and chips hold one selection (browseSelection): a tab opens on its first entry, and a new choice clears the last. Only the Filters dropdown combines; era, length, type and sort survive tab changes. Every single selection gets a heading from listHeading.
- SEO: every card, tab, chip and film-page label is a real <a href> to its clean URL; softClick keeps the in-page navigation on a plain click. Each page has one h1 (the header logo is not one). Don't turn these back into buttons: Google only follows links.
- Single-selection list pages are ranked "best" lists: rankFilms (Editor's Choice, Essential, then IMDb/RT) is their default order, subjects, topics and moods get "The N Best …" titles where N is the whole list and every title is numbered, and directors get "… Documentaries, Ranked". listHeading owns this; intros are hand-written in src/data/list-intros.ts.
- A list under eight titles (MIN_LIST), or a director who isn't featured, is noindex and stays out of the sitemap, /best and the footer index; listGroups applies the rule for all three. /moods/x is a clean URL like the others.
- JSON-LD comes from src/lib/structured-data.ts through pageHead: Movie/TVSeries on films, ItemList on lists, BreadcrumbList, WebSite/Organization on home. Never add AggregateRating from IMDb or RT scores; Google forbids marking up other sites' ratings.
- "Documentaries like X" pages (/documentaries-like/x, the like search param) exist only for films in src/data/like-pages.ts: hand-picked `add` titles first, then documentariesLike's matches (topic tags, category, Go in blind, moods), 12 at most. Intros there are hand-written. Those films' pages swap "More like this" for an "If you liked X →" row linking to their page.
- Decade pages (/decades/x, DECADES in discovery) reuse the era param: a decade is a page only when nothing else is selected; beside a tab selection it stays an era filter on that page's URL.
- Streaming pages (/netflix, /prime-video, /disney-plus, /bbc-iplayer, /hbo-max; pick=<service id>, SERVICES in src/data/streaming.ts) list titles streaming on that service in Ireland, the UK or the US, from src/data/streaming-availability.json, a dated snapshot from `npm run streaming-availability` (TMDB's JustWatch providers, needs TMDB_READ_ACCESS_TOKEN). One page per service, not per country: Netflix's country lists were near-identical and would compete in search, so /netflix/ireland|uk|us only lead to /netflix. Pages never fetch providers catalogue-wide. Rerun the script monthly, then republish and IndexNow; titles carry the checked month, and intros name no films because availability changes. JustWatch doesn't track RTÉ Player or Apple TV well enough for a page; never invent availability.
- Page titles end " | Documentary Club" (no em dash).
- Weekly email signups go to a Kit double opt-in form through subscribe in src/lib/newsletter.functions.ts, using the KIT_API_KEY and KIT_FORM_ID secrets. Each signup carries its placement (footer, film, surprise, saved, best, list) in Kit's "source" custom field and the referrer's utm_medium, plus a consent-gated GA newsletter_signup event. NewsletterSignup is one email field and a button; never add popups. subscribe reports success only after Kit returns 2xx for both calls; every failure, the honeypot included, shows the error and logs a `[newsletter]` line with the reason and Kit's status and body.
- After publishing new or renamed pages, `npm run indexnow` submits every sitemap URL to IndexNow (Bing and others). It needs the key file in public/ to be live, so run it only after the user has published.
- Free on YouTube: a film is tagged when its full film is free on YouTube (free-with-ads YouTube Movies count; rentals don't) and plays in at least one of Ireland, the UK or the US. The link is the CSV youtube_id. `npm run youtube` scans trusted channels and searches by title; `npm run youtube -- check` drops a link only when the video is gone or plays in none of those regions; a scheduled task runs it on the 1st of each month. Any full upload counts, official or not and however new (English audio, not a dubbed copy, not split into parts): the owner wants as many films linked as possible, and the monthly check removes the ones taken down. Prefer the rights holder's upload when there is one, because it lasts. Hark fills in docs/youtube-to-find.csv (unlinked films in rank order); verify every returned link with the API before applying it. The youtube_regions column (written by apply and check) lists where a link plays when it isn't all three; the film page's "Watch free on YouTube" button adds a muted "US only"-style note only for visitors outside those. On /tags/free-on-youtube the browser hides links blocked in the visitor's country (youtubePlaysIn; only IE/GB/US are known, so elsewhere nothing is hidden) with a "Show all regions" toggle, and an "Award winners" pill keeps films with a win (wonAward). Both are in-page view filters, not pages; the server renders the whole list. It also has its own browse tab after Tags ("Free on YouTube", "YouTube" on phones); the Tags row leaves it out. On phones the seven tabs scroll sideways with a fade on the right, and the selected tab scrolls into view.
- The site is an installable web app (PWA): public/manifest.webmanifest, home-screen icons from `npm run app-icons` (rerun after changing favicon.svg), Apple meta tags in __root, and public/sw.js, registered in production only. The worker fetches pages network-first (the cache is only an offline fallback, so a publish shows at once), caches build files, posters and icons, and never touches /_serverFn or other sites, so providers and signups stay live. Bump its cache names when changing what it stores. About tells visitors how to add it to their home screen; no install popups.
- Older iPads must keep working: vite.config sets build.target to Safari 15 (Vite's default, Safari 16.4, left class static blocks in the bundle, so iPadOS 15 and early 16 parsed nothing, never hydrated, and only plain links worked). __root adds an inline Object.hasOwn and .at() fallback for iPadOS 15.0–15.3. Don't raise the target without checking the bundle with esbuild --target=safari15.
- Optional Google sign-in syncs Saved and Watched across devices (Firebase project documentary-club, free Spark plan, Firestore in eur3; console under colinfitz@gmail.com). Each account is one document, users/{uid} = { shortlist, watched, updatedAt }, and the published rules let only its owner read or write it, with no other fields. Logic: src/lib/cloud-sync.ts (merge rules, tested) and src/hooks/use-cloud-sync.ts (I/O); the AccountSync panel sits on the Saved and Watched lists only. Firebase loads lazily: only on those lists or for browsers with the dc-account flag, so other visitors never download it, and it must be loaded before the tap because iOS blocks popups that wait on a download. The first sign-in on a device merges local and account lists (watched wins over saved); after that the account is the source of truth. localStorage stays the offline copy and the site works fully without signing in. Never add other personal data or a sign-in popup/prompt.
- Tips go through Ko-fi as a plain link (KOFI_URL in src/components/support.tsx, ko-fi.com/documentaryclub): one muted line above the footer on every page except About, where a card sits under the first paragraph, with a consent-gated support_click GA event. No Ko-fi widget script, floating button or popup.
- The weekly email is a Kit broadcast built from docs/newsletter/issue-N.html (table layout, inline styles, pasted into one Kit HTML block). Weekly pick comes from Editor's Choice; awards, ratings and facts come from the CSV and snapshot only.
- Coming Soon (/coming-soon, browse=soon, its own tab before About) lists upcoming documentaries and ones in cinemas now from src/data/coming-soon.json, a dated snapshot from `npm run coming-soon` (TMDB, needs TMDB_READ_ACCESS_TOKEN). It holds one list per country in the site's country list (shared titles, per-country date and where line), and the page shows the visitor's country (the same detected/saved country as streaming providers) with a picker; a country with under six titles gets no list and sees the US one with a note. IE, NZ, AT and CH also use their neighbour's dates (GB, AU, DE) when TMDB has none of their own, labelled e.g. "In cinemas in the UK". Coming soon and In cinemas now are a two-button in-page switch; both lists are server-rendered. A title needs a YouTube trailer and a confirmed cinema (release types 2, 3) or digital (4) date in that country; festival premieres (type 1) never count, and TMDB's free-text release notes are only shown when they name a known service. data/coming-soon-hide.txt holds hand-removed TMDB ids (concert films, mockumentaries). Rerun monthly with the streaming snapshot, then republish. Pages never query TMDB for this live.
